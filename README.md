# 野径 · 华南徒步图鉴（YEJING · South China Trails）

用 Vue 3 + Vite 写的华南徒步与景点路书站点：76 个点位、53 条线路、11 座城市、74 项装备。  
每个点位都能看到四季表现、日落和夜景的时间与位置、机位怎么找、附近吃什么、怎么坐车到起点；  
每条线路还能按里程 / 爬升 / 天数 / 地形自动列出**这条线专属的装备清单**。

> 当前状态：**本地开发版本，未推送 GitHub**。可通过下面的在线链接随时查看（每次改完重新发布即可覆盖同一链接）。

### 数据勘误：岳麓山·桃花岭穿越

这条线的名字容易被读成「岳麓山进、桃花岭出」，实际不是：

| | 实际 |
|---|---|
| 起点 | **湖南大学东方红广场**（地铁 4 号线湖南大学站 2 号口） |
| 终点 | **梅溪湖**（地铁 2 号线梅溪湖东站） |
| 名称里的「岳麓山」 | 中途翻越的主峰段（爱晚亭—麓山寺—山顶电视塔），是**途经**，不是起点 |
| 名称里的「桃花岭」 | 中途穿越的桃花岭野径（垭口—水库），是**途经**，不是终点 |

路线详情页的「概览与轨迹」顶部有一张琥珀色**命名说明卡**，把上面这四项并排列出，并解释误读的由来；
标题下方也固定显示「起 湖南大学（东方红广场） → 终 梅溪湖」，不用点开也知道两头在哪。

### 搜索只认两种写法

- **景点页**：只认地名（城市 / 省份 / 区县）。输入别的字会直接提示「这个搜索框只认地名」，不给无关结果。
- **路线页**：地名（韶关）或「徒步名称 + 路线」（武功山徒步、船底顶 罗新线）。带 `徒步/路线/穿越/环线/登顶/古道/海岸线` 或以空格分隔时按路线名匹配，否则先看是不是地名，都不是就提示支持的两种写法。

同一个匹配函数（`src/utils/search.js`）仍然支持单字：输入「山」会列出所有含「山」的条目。

### 卡片交互：双击图片看图，双击文字进下一页

两类列表（`/spots`、`/routes`）用同一套规则，避免「双击被单击抢走」：

| 操作位置 | 结果 |
|---|---|
| 单击卡片（图片或文字） | 选中，景点页同时把右侧地图飞到该点位并弹气泡 |
| **双击封面图** | 打开全屏看图（`LightBox.vue`），把当前筛选结果串成画廊 |
| **双击文字区** | 进入下一个界面（景点路书 `/spot/:name`、路线详情 `/route/:id`） |
| 点「看路书 →」/「进入详情 →」按钮 | 同上，给不习惯双击的人留的入口 |

关键点：卡片本身**不再**绑 `@click` 跳转，否则双击的第一下就把页面切走，`dblclick` 永远等不到（之前「双击打不开图」就是这个原因）。
实现上把双击统一挂在 `<article>` 上，用 `e.target.closest('.cover')` 判断落点，避免 `<img>` 拖动或子元素拦截导致丢事件。

构建产物用内容哈希命名（`assets/app-<hash>.js`），改完刷新即可看到新版，不会因为浏览器缓存旧 `app.js` 而「改了没反应」。

`LightBox.vue`：左右键 / 箭头按钮切换、Esc 关闭、手机左右滑；顶部显示「当前 / 总数」，底部有图注与跳转入口。
详情页顶部大图同样双击看大图（整个 hero 都能双击，「返回」按钮除外）；「双击看大图」的小圆角提示**平时隐藏**，鼠标移进图片才淡入，不压画面。

### 返回与回顶部

- 详情页左上角「返回景点列表 / 返回路线列表」：上一页是列表时走 `router.back()`，回到**原来那屏**；直接打开详情（没有历史）时退回列表首页。
- 列表页用 `src/utils/viewState.js` 记住筛选条件与滚动位置（内存 + sessionStorage 双写），返回时还原，不会跳回顶部。
- 全局 `BackTop.vue`：滚过 520px 后**右上角**（导航下方、右侧留白处，不压地图）浮出圆形按钮，带阅读进度环，点了平滑回到顶部；窄屏（≤760px）自动回到右下角并隐藏百分比。


### 路线详情：五个页面 + 外部跳转

`/route/:id?tab=overview|shots|guide|gear|supply|more`

- **概览与轨迹**：高德矢量 / 天地图卫星双底图 + 途经点 + 海拔剖面，地图下方直接给「在两步路看真实轨迹」的按钮
- **四季与光**：本线封面 + 同一条山系最近点位的春/夏/秋/冬/晚霞/夜色，每张都标了来源与距离，点开可翻页
- **分段路书**：逐节点里程/海拔/路况表 + 交通接驳 + 出片机位，附「高德导航到起点」
- **装备清单**：按天数判场景、按里程算水量与路餐、按补给点与地形追加专属项
- **补给与风险**：补给点、撤离原则、风险标签、官方提示
- **更多跳转**：两步路（搜索全部 / 只看轨迹）、小红书、抖音、天地图网页版、高德导航、导出 GPX、同城景点
- **我的这条线**：给自己留笔记与链接（Pinia + localStorage），卡片上会显示条数

两步路的跳转就是用户给的格式，只换关键词：
`https://www.2bulu.com/search/search_all.htm?searchRange=all&keyword=<路线名>`

### 搜索：输入一个字就能命中

景点页与路线页都用同一套宽松匹配（`src/utils/search.js`）：先试整串包含，不中就把查询按字拆开，  
要求每个字都出现。所以输入「山」会列出所有含「山」的点位与路线，输入「武功山」也能命中「山·武功」这种写法。  
景点会把名称、城市、区县、类型、推荐理由、标签一起丢进去匹配；路线匹配名称、城市、省份、地形、难度、天数。

### 景点路书弹层（5 个标签）

- **日落 · 夜景**：顶部一条**按经纬度实算**的日照信息（今日日落 / 暖光开始 / 太阳落点方位 / 蓝调时刻），下面两张卡片各配 4 条要点：时间窗口、落点方位、光线怎么走、相机参数。配图优先用**该点位自己的黄昏与夜景实拍**（`lightPhoto.js`，76 个点位各抓 2 张，下载时用亮度 + 色温筛选，白天图进不来），没有才退到同城最贴合那个时段的一张，图注明确区分「本点位实拍」与「同城实拍」
- **四季看点**：春 / 夏 / 秋 / 冬四张卡片，**每季一张该景点的实拍**（`seasonPhoto.js`，76×4=304 张，按「景点名 + 季节」检索，剔除截图、拼图、带大字的推广图、夜景图），图上标季节、写清月份、适合度和一句话理由。某季实在找不到就显示「暂无该季实拍」，不拿别的季节凑数
- **机位与走法**：具体机位（怎么找到、什么时段、参数建议）+ 推荐走法 + 其他机位
- **吃什么**：按城市给 4-6 家老店，含招牌、人均、位置、排队提示；点链接直接跳到小红书 / 抖音搜同款
- **怎么去**：交通接驳 + 实用提醒 + 标签，附小红书 / 抖音搜索入口

### 景点路书页（`/spot/:name`）

结构对齐路线详情页：大图 + 常驻分页（概览 / 四季 / 日落与光 / 机位与走法 / 吃什么 / 怎么去）。

**创新点**是概览里的「今天的这条光线」板：左边是按经纬度实算的时间轴（暖光开始 → 日落 → 蓝调），
右边是一个 SVG **光线罗盘**，把太阳落点的方位角画成指针（例如 253° 西偏南），
出门前一眼就知道该朝哪个方向架机器。下面还给了「同城还能去哪」，可以直接串成一天的路线。

### 装备清单（两层）

1. **总清单**（`/gear`）：`src/data/gear.js` 里的 74 项，源自用户提供的《户外装备清单》，  
   按着装 / 背负 / 宿营 / 行进 / 饮食 / 导航 / 急救 / 杂物八大系统分组，  
   每项带「必带」标记、适用场景、以及一句「为什么带」。
2. **每条路线专属**（路线详情 → 04 装备清单）：`src/data/routeGear.js` 按  
   **天数 → 场景**（1 天单日徒步 / 2 天重装露营 / 3 天以上长线高难度）先定档，  
   再用里程和爬升算出预计耗时、建议水量、路餐份数、背包容量，  
   并结合途经点的 `sup`（有无水源、有无补给）与 `tips`（雷雨、夜爬、低温）生成 3-5 条针对性提醒；  
   最后按地形族（海岸 / 溪谷 / 高山 / 森林 / 丹霞 / 峰林 / 石阶 / 花岗岩）追加这条线特有的装备，  
   例如海岸线加「防滑礁石手套 + 手机防水袋」，溪谷加「溯溪鞋 + 干爽替换衣物」。  
   每一项都带一句解释，写着「为什么这条线要带」而不是通用话术。

勾选状态用 Pinia（`src/stores/gear.js`）管理并写到 localStorage，总清单与每条路线各自独立计数。

### 地图：高德矢量 + 天地图卫星

`HikeMap.vue` 右上角可切两种底图：

- **高德矢量**：`webrd0{s}.is.autonavi.com` 的 `style=8`，坐标需从 WGS84 纠偏到 GCJ-02
- **天地卫星**：天地图 WMTS 影像 `img_w` + 影像注记 `cia_w`，`tk=01a165dff03ee02cc289d9958aa93768`，  
  坐标本身就是 WGS84 / CGCS2000，**不纠偏**

两套底图的基准不同，所以切换时会重设 `toLL` 并重绘点位、轨迹、途经点——不然红线会整体偏移几百米。  
天地图的 key 是「浏览器端」类型，绑定了域名白名单：如果线上域名没加进白名单，会返回 403，  
这时地图上会浮出一条提示告诉你去控制台加域名。

## 图片抓取与补图

图片不硬编码，脚本生成清单，组件只读清单：

```
scripts/
  import_gallery.py    # 图集 HTML → 3:2 裁切 → 110 张入 public/photos/gal/
  fetch_hd.py          # 按景点名检索 1500 px 高清候选（360 图片 imgurl），带关键词表
  install_hd.py        # 选定候选 → 3:2 裁切 + LANCZOS + UnsharpMask + q92
  check_water.py       # 高德瓦片像素判水（(2k+1)² 邻域中位数，避开 POI 图标误导）
  trace_trail.py       # 瓦片 → 白/黄/绿/水代价图 → 最小代价路径，逐段追出步道走向
  trace_all.py         # 53 条批量追踪（并发抓瓦片 + 缓存 scripts/_tiles）
  rebuild_from_traces.py  # 追踪结果写回 routes.js 的 path，并做落水与里程自检
  render_track.py      # 离线拼瓦片出图，用于逐条目检轨迹
  fetch_photos.py      # Commons 搜索（中文名 + 排除词）
  build_photos.py      # 合并候选 → 下载 → 生成 src/data/spotWiki.js
  fetch_mood.py        # 日落 / 夜景 氛围图（按地貌主题，现已被同城实拍取代）
```

补一张图最省事的办法：把图片放进 `public/photos/`，在 `src/data/spotWiki.js` 里加一行

```js
"大梅沙": { src: "/photos/spot-31-1.jpg", all: ["/photos/spot-31-1.jpg"], title: "大梅沙", credit: "作者", license: "CC BY-SA 4.0", page: "原图页地址" },
```

换成自己拍的照片（把 `credit` 写成自己）就没有版权问题。

## 已知限制

1. 照片已全覆盖（76/76、53/53），封面 110 张全部 ≥1200 px，四季 304 张 ≥900 px、日落夜景 150 张 ≥900 px；大部分是网络博主图 / 公开图源，仅作毕设演示；原图集自带的作者水印（小红书号、VCG、红网等）按署名保留，未做涂抹。
2. 轨迹是「沿可见步道路网的走向示意」，不是 GPX：地图上能识别的白线步道会照着走，但**关键点太稀的线路（如大熊山 3 个点、虎跳峡 4 个点）画出来的里程会短于标注全程**，看里程以左侧数字与海拔剖面为准。要 GPS 级精度，把 `routes.js` 里的 `path` 换成 GPX 解析结果即可，组件不用改。
3. 没有后端：筛选、排序、导出 GPX 全在浏览器端完成，`dist/` 可直接丢静态托管。
4. 小红书 / 抖音 / 两步路没有做内容抓取（涉及登录与版权），只提供关键词跳转。
5. 维基接口在部分网络下限流严重（HTTP 429），批量补图建议分几次跑，脚本会断点续抓。四季与日落夜景图是按「景点名 + 季节/时段」检索后再筛的，绝大多数是该景点本人，但**个别小众点位可能混入同城画面**——这类图在图注里会写成「同城实拍」，看到「本点位实拍」才保证是原地原景。
6. 账号是**本地演示版**：注册信息、会话、收藏都存在浏览器 `localStorage`（键前缀 `yj.`），换设备、换浏览器、清缓存即全部丢失；密码虽有加盐 SHA-256，但校验在前端完成，挡不住改代码，别当真实账号系统用。要真账号得配后端（见 `docs/旅游社交平台-系统设计.md`）。
7. **一个工作区只能对应一个在线应用**：当前线上应用是「华南徒步地图」（`south-china-hiking`），再调用发布都会覆盖同一个链接，无法并存「正式版 + 某个历史存档版」。所以 10:21 版存档（`archive-1021/`）没有独立在线链接，只有离线存档；要给它单独的链接，得把这套文件复制到另一个工作区去发布。
8. 顶部导航在 1000–1920 px 之间做过收紧：1240 px 以下压缩图标与内边距，1080 px 以下隐藏标签副标题。1092 px 与 1440 px 实测五个标签（含「装备清单」）都完整显示；再窄（<1000 px）标签栏改为可横向滑动，窄屏下最后一项需要滑一下才露全。

## 数据层：两套 MySQL

站点的内容原来全在前端 `src/data/*.js` 里，账号与收藏只在浏览器。想搬到服务端时手上有两套库，各管一段：

| 目录 | 库名 | 规模 | 装什么 |
|---|---|---|---|
| `sql/` | `yejing_content` | 14 表 + 3 视图 | **本站的全量真实数据**：24 城 / 76 点位 / 53 路线 / 74 装备 / 218 关键点 / 39113 轨迹点，外加账号、会话、收藏 |
| `db/` | `yejing` | 23 表 + 2 视图 + 3 触发器 | 社交平台的完整设计（帖子、评论、关注、找搭子、私信、审核），配 `docs/旅游社交平台-系统设计-MySQL版.md`，只有十几行演示数据 |

```bash
# 内容库（全量数据）
mysql -u root -p < sql/01_schema.sql
mysql -u root -p yejing_content < sql/02_seed.sql

# 平台库（演示数据）
mysql -u root -p < db/01_schema.sql
mysql -u root -p < db/02_seed.sql
```

`sql/02_seed.sql` 是生成物，别手改：改完 `src/data/*.js` 跑 `node scripts/export_mysql.mjs` 重新生成。两套库都用 `sqlglot` 按 MySQL 方言验过语法，但**都没有在真实 MySQL 实例上跑过**（本机没装服务）。

> 线上链接是纯静态托管，**没有数据库**。这两套 SQL 只能跑在自己的服务器 / 云 MySQL 上，前端要接得先有后端 API。

## 技术栈

站点同时用了几个互补的前端技术：

| 层  | 用什么                                           | 干什么                             |
| -- | --------------------------------------------- | ------------------------------- |
| 视图 | **Vue 3**（`<script setup>` + Composition API） | 页面与组件                           |

| 状态 | **Pinia**                                     | 装备勾选状态，跨页面共享 + localStorage 持久化 |
| 地图 | **Leaflet 1.9**                               | 高德矢量 / 天地图卫星双底图、轨迹、途经点          |
| 图表 | 手写 **SVG**                                    | 海拔剖面、城市散点、热度条                   |
| 样式 | 原生 **CSS**（scoped + CSS 变量）                   | 无 UI 框架，避免打包体积                  |
