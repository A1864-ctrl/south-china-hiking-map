# 野径 · 旅行社交平台 —— 系统设计说明（v2）

> 本文是「野径 · 华南徒步图鉴」从**静态内容站**升级为**带完整账号体系的旅游社交平台**的设计稿。
> 第一部分对齐上一版已有结果，第二部分给出新系统的前后端设计。
> 目标读者：毕业设计评审 / 技术方案评审 / 后续开发。

---

## 第一部分　基线：上一版做了什么（v1 静态站）

### 1.1 定位

纯前端内容站，解决「华南去哪徒步、什么时候去、怎么拍」的问题，无账号、无后端、无 UGC。

### 1.2 数据资产

| 类别 | 数量 | 说明 |
|---|---|---|
| 景点点位 | 76 | 覆盖 11 座城市，含经纬度、类型、热度、票价、建议时长 |
| 徒步路线 | 53 | 含里程、爬升、天数、难度、途经点、装备、风险 |
| 装备条目 | 74 | 八大系统分组，标注必带与适用场景 |
| 封面图 | 110 | 景点 76 + 路线 53（去重后 110 张），≥1200px |
| 四季图 | 304 | 76 × 春夏秋冬 |
| 日落 / 夜景图 | 150 | 每点位 2 张，按亮度与色温筛选 |
| 城市 | 11 | 广州、深圳、桂林、长沙、湘西、张家界、惠州、郴州等 |

### 1.3 技术栈

Vue 3（`<script setup>`）+ Vite 5 + vue-router 4（hash）+ Pinia + Leaflet 1.9（高德矢量 / 天地图影像双底图）+ 手写 SVG 图表。

### 1.4 已实现能力

- 景点路书：概览 / 四季 / 日落与光（按经纬度实算日照 + SVG 光线罗盘）/ 机位与走法 / 吃什么 / 怎么去
- 路线详情：概览与轨迹、四季与光、分段路书、装备清单（按天数场景推导）、补给与撤离、更多跳转
- 装备清单：总清单 + 每条路线专属，勾选状态 localStorage
- 交互：卡片双击分流（图片看大图 / 文字进详情）、返回列表保留筛选与滚动位置、右上角带进度环的返回顶部
- 内容纠错：岳麓山·桃花岭穿越的起终点勘误卡

### 1.5 已知边界

无账号 → 不能收藏、不能发帖、不能找搭子；轨迹为「走向示意」非实测 GPS；内容全部静态写入 `src/data/*.js`。

## 第二部分　新系统设计

## 2.1 产品定位与角色

**一句话**：把 v1 的「查路线」变成「查路线 → 收藏 → 约人 → 一起走 → 回来发帖」的闭环。

| 角色 | 核心诉求 | 对应功能 |
|---|---|---|
| 游客 | 看内容、比路线 | 免登录浏览、搜索、地图 |
| 注册用户 | 存下来、留痕 | 收藏景点 / 路线、足迹、草稿 |
| 内容作者 | 表达、涨粉 | 发帖、图文、被点赞 / 评论 / 关注 |
| 组队者 | 找到强度匹配的人 | 找搭子、附近的人、私信 |
| 运营 | 审核、推荐 | 后台审核、榜单、风控 |

## 2.2 总体架构

```
客户端            Vue 3 SPA（Web / PWA）        微信小程序（同源 API）
                        │  HTTPS
接入层            CDN（静态 + 图片）  →  Nginx（TLS / gzip / limit_req / 灰度）
                        │
应用层            FastAPI 单体分模块（后续可拆）
                  auth │ content │ social │ match │ track │ media
                        │
中间层            Redis（会话 / 缓存 / GEO / 限流 / 队列）
                  Celery Worker（图片处理 / Feed 扩散 / 审核 / 统计）
                        │
存储层            PostgreSQL 16 + PostGIS 3.4      MinIO / S3（原图、GPX、geobuf）
```

**为什么先单体**：团队规模与流量决定拆分时机。模块间用领域边界（`app/modules/*`）隔离，通过依赖注入调用，未来按 `social`、`track` 拆服务时不需要改调用方。

## 2.3 数据模型（PostgreSQL + PostGIS）

核心表（省略审计字段）：

```sql
-- 账号
create table app_user (
  id            bigserial primary key,
  phone         varchar(20) unique,
  email         citext unique,
  password_hash text,                       -- Argon2id
  nickname      varchar(32) not null,
  avatar_key    text,
  gender        smallint,                   -- 0 未知 1 男 2 女
  bio           varchar(200),
  status        smallint default 1,         -- 1 正常 2 禁言 3 封禁
  created_at    timestamptz default now()
);

-- 设备 / 会话审计（Redis 是热数据，这里是冷备）
create table user_device (
  id         bigserial primary key,
  user_id    bigint references app_user(id),
  device_id  varchar(64) not null,
  ua         text, last_ip inet,
  last_seen  timestamptz,
  unique (user_id, device_id)
);

-- 景点 / 路线（沿用 v1 的数据，迁入库）
create table poi (
  id       bigserial primary key,
  name     text not null,
  city     text, category text,
  geom     geography(Point, 4326) not null,
  props    jsonb
);
create index poi_geom_idx on poi using gist (geom);

create table trail (
  id           bigserial primary key,
  name         text not null,
  distance_km  numeric(6,2),
  climb_m      int,
  days         smallint,
  geom_simpl   geography(LineString, 4326),  -- 抽稀后的预览线
  geom_key     text,                          -- 全量轨迹在对象存储的 key（geobuf）
  bbox         box2d
);
create index trail_geom_idx on trail using gist (geom_simpl);
create index trail_bbox_idx on trail using gist (bbox);

-- 收藏（多态）
create table favorite (
  user_id     bigint not null,
  target_type smallint not null,   -- 1 景点 2 路线 3 帖子
  target_id   bigint not null,
  created_at  timestamptz default now(),
  primary key (user_id, target_type, target_id)
);
create index favorite_target_idx on favorite (target_type, target_id);

-- 内容
create table post (
  id         bigserial primary key,
  author_id  bigint references app_user(id),
  trail_id   bigint, poi_id bigint,
  title      varchar(120), body text,
  images     jsonb,                 -- [{key,w,h,blurhash}]
  like_cnt   int default 0, comment_cnt int default 0,
  status     smallint default 1,    -- 1 已发布 2 审核中 3 驳回
  created_at timestamptz default now()
);
create index post_author_time_idx on post (author_id, created_at desc);

-- 找搭子
create table buddy_post (
  id          bigserial primary key,
  owner_id    bigint references app_user(id),
  dest_city   text not null,
  trail_id    bigint,
  start_date  date not null,
  end_date    date not null,
  level_req   smallint,             -- 1 入门 2 进阶 3 顶级
  budget      int,
  gender_pref smallint default 0,   -- 0 不限 1 男 2 女
  slots       smallint default 1,   -- 还差几人
  tags        text[],
  geom        geography(Point,4326),
  status      smallint default 1,
  created_at  timestamptz default now()
);
create index buddy_city_date_idx on buddy_post (dest_city, start_date, end_date);
create index buddy_geom_idx on buddy_post using gist (geom);

-- 附近的人（最后一次位置，覆盖写）
create table presence (
  user_id    bigint primary key,
  geohash6   char(6) not null,
  geom       geography(Point,4326) not null,  -- 已加抖动的模糊点
  updated_at timestamptz default now()
);
create index presence_geom_idx on presence using gist (geom);
```

**设计要点**

1. **空间类型统一 `geography`**：按米计算，避免 `geometry` 在高纬度变形。
2. **轨迹双存**：库内只放抽稀线（几千点以内）供列表/预览，全量放对象存储；详情页按需拉取。
3. **多态收藏用联合主键**：避免三张表；查询热点是「某用户收藏列表」，主键前缀正好覆盖。
4. **计数字段冗余**：`like_cnt`、`comment_cnt` 冗余在 `post` 上，异步校正，避免每次 count(*)。

## 2.4 前端设计

### 2.4.1 UI 设计思路

- **色彩**：森林绿 `#2D5A3D`（主）/ 砂岩 `#C4A35A`（辅）/ 米白 `#F6F2E9`（底），沿用 v1 的自然色系，保证升级不断层。
- **栅格**：8pt 基准，间距 8/16/24/32；内容最大宽 1320，正文行宽 ≤ 72ch。
- **层级**：两档字重（400/500）+ 三档字号（13/15/20），靠留白和分割线而不是阴影堆层级。
- **组件**：Design Token（CSS 变量）+ 原子组件（Button / Card / Tag / Sheet / Skeleton），Storybook 维护；地图、编辑器、图集三个重组件单独分包。
- **暗色**：Token 双值（`--bg`, `--fg`），`prefers-color-scheme` + 手动覆盖，图片加 6% 暗遮罩避免刺眼。

### 2.4.2 动效方案

| 场景 | 手段 | 细节 |
|---|---|---|
| 路由切换 | View Transitions API，降级 CSS `fade+translateY(6px)` | 180ms，`mode="out-in"`，避免布局跳动 |
| 列表增删 / 排序 | FLIP（First-Last-Invert-Play） | 收藏、筛选时卡片位置平滑过渡 |
| 图片加载 | blurhash 占位 → 模糊图 → 原图，`content-visibility: auto` | 首屏 LCP 控制在 2.5s 内 |
| 滚动显现 | IntersectionObserver 一次性触发 | `translateY(12px)+opacity`，不进视口不渲染 |
| 点赞 | 心跳缩放 + 粒子（Canvas，仅点赞瞬间） | 90ms，`prefers-reduced-motion` 下关闭 |
| 双击看图 | LightBox 缩放入场（scale 0.94→1） | 与 v1 的卡片双击分流保持一致 |
| 下拉刷新 / 手势 | 触摸位移 + 阻尼函数 | 移动端 PWA |

原则：**动效只解释状态变化，不做装饰**；所有动画 ≤ 300ms，可中断（用户滚动立即取消）。

### 2.4.3 交互与工程

- 服务端状态用 TanStack Query（缓存、失效、重试），本地 UI 状态用 Pinia，两者不混。
- **乐观更新**：点赞 / 收藏先改本地，失败回滚并 toast。
- **离线**：发帖草稿写 IndexedDB，联网后 Background Sync 补发；地图瓦片 LRU 缓存。
- **无限滚动 + 虚拟列表**：长列表只渲染视口 ± 2 屏。
- **无障碍**：焦点环、`aria-live` 播报、键盘可达、`prefers-reduced-motion`。
- **性能预算**：首屏 JS ≤ 180KB（gzip），路由级 code-split，图片 AVIF/WebP + `srcset`，CDN 预热。

## 2.5 账号体系

### 2.5.1 注册

三种入口：手机号 + 短信验证码、邮箱 + 密码、微信 OAuth（`snsapi_login`）。

```
POST /api/v1/auth/sms/code      { phone }            → 60s 限一次，验证码存 Redis sms:{phone} TTL 300s
POST /api/v1/auth/register      { phone, code, password, nickname }
POST /api/v1/auth/login         { account, password | code }
POST /api/v1/auth/refresh       { refresh_token }
POST /api/v1/auth/logout
```

- 密码：**Argon2id**（`time_cost=3, memory_cost=64MB, parallelism=4`），不可逆、抗 GPU。
- 唯一性：`phone`、`email` 唯一索引；注册并发冲突由数据库约束兜底，捕获 `unique_violation` 返回「已注册」。
- 验证码：Redis 存哈希值（不存明文），错误 5 次锁定 15 分钟。

### 2.5.2 登录态：双 Token

| 令牌 | 形态 | 有效期 | 存放 |
|---|---|---|---|
| access_token | JWT（HS256，`sub/jti/dev/exp`） | 15 分钟 | 内存（Pinia），不进 localStorage |
| refresh_token | 256bit 随机串 | 7 天（可「记住我」延长 30 天） | HttpOnly + Secure + SameSite=Lax Cookie |

- access 过期 → 前端拦截 401 → 用 refresh 换新（**旋转**：旧 refresh 立即失效，复用旧值视为盗用，整设备下线）。
- refresh 白名单存 Redis：`rt:{uid}:{jti}`，登出即删。

### 2.5.3 Redis 会话保持（重点）

「登录后一定时间内重新访问无需重复登录」靠的是**滑动过期**：

```
登录成功
  ├─ 生成 jti = uuid4()
  ├─ Redis: SETEX sess:{uid}:{jti} 1800 {device, ip, ua, last_seen}
  └─ 返回 access + refresh

每次带 access 的请求
  ├─ 中间件验签 → 查 Redis sess:{uid}:{jti}
  ├─ 命中 → EXPIRE sess:{uid}:{jti} 1800   （滑动续期：只要 30 分钟内来过就不断）
  └─ 未命中 → 401，前端走 refresh 流程

30 分钟无请求 → key 自动过期 → access 失效
  ├─ refresh 仍在有效期 → 静默换新 access，用户无感
  └─ refresh 也过期 → 跳登录页，保留 redirect 参数
```

**为什么不用纯 JWT**：JWT 自包含无法撤销。改成「JWT 只做签名校验 + Redis 存会话位」，就同时得到**无状态校验的性能**与**可踢人、可统计在线、可限并发**的能力。

- 踢下线：`SCAN sess:{uid}:*` 批量删；单设备踢：删对应 jti。
- 在线统计：`SETEX online:{uid}` 简化版，配合 HyperLogLog 做 UV。
- 异地登录：登录时比对 `last_ip` 的城市，差异大则要求二次验证。

### 2.5.4 安全清单

CSRF（SameSite + double submit）、登录限流（`5 次/分钟/手机号`，Redis 令牌桶）、密码强度、敏感操作二次验证、设备指纹、内容审核。

## 2.6 收藏与社交

### 2.6.1 收藏

- 接口：`POST /favorites`、`DELETE /favorites`、`GET /favorites?type=&cursor=`
- 计数：Redis `HINCRBY cnt:fav {type}:{id} 1`，Celery 每 30s 批量落库，读时优先 Redis。
- 列表：游标分页（`created_at, id` 复合游标），避免深分页 `offset`。

### 2.6.2 发帖与 Feed

- 发布：正文 + 最多 9 图 + 关联路线/景点；图片直传对象存储（后端签发预签名 URL），异步转码 3 档尺寸。
- **推拉结合**：
  - 普通用户（粉丝 < 5000）：发帖后写扩散，把 `post_id` 推进粉丝的 `feed:{uid}` ZSET（score=时间戳），最多推 5000 人。
  - 大 V：不推，读时拉取其最近 N 条。
  - 读：`ZREVRANGE feed:{uid} 0 49` + 合并大 V 列表 → 按时间归并 → 批量取详情。
- 冷启动 / 新用户：按兴趣标签召回热门帖兜底。
- 互动：点赞写 Redis Set 去重 + `INCR`，异步落库；评论走消息队列做审核后可见。

## 2.7 找搭子匹配

### 2.7.1 结构化需求

目的地城市、日期区间、强度等级、预算、性别偏好、还差几人、兴趣标签。

### 2.7.2 两段式匹配

**第一段：硬过滤（SQL，走索引）**

```sql
select * from buddy_post
where status = 1
  and dest_city = :city
  and daterange(start_date, end_date, '[]') && daterange(:start, :end, '[]')
  and (:level is null or level_req <= :level + 1)
  and (gender_pref = 0 or gender_pref = :my_gender)
order by start_date
limit 200;              -- 候选池上限，避免全表打分
```

**第二段：打分排序（应用层，200 条内计算）**

```
score = 0.35 × 时间重叠度      # 重叠天数 / 较短行程天数
      + 0.25 × 偏好相似度      # 标签 Jaccard + 强度差惩罚
      + 0.15 × 活跃度          # 7 日内登录 / 发帖次数，归一化
      + 0.15 × 信誉分          # 完成率、被举报扣分、实名加分
      + 0.10 × 距离衰减        # exp(-d/50km)
```

- 时间重叠度为 0 直接丢弃（硬约束）。
- 结果缓存：`buddy:{city}:{date}:{level}` 缓存 5 分钟；有人发新帖时按城市失效。
- **双向同意**才能开聊：发起「打招呼」→ 对方同意 → 建会话；每日打招呼配额 10 次，防骚扰。

## 2.8 地图与轨迹数据

### 2.8.1 底图

沿用 v1 的双底图经验：高德矢量（GCJ-02，需纠偏）+ 天地图影像（WGS84/CGCS2000，不纠偏）。**切换底图必须重算坐标并重绘**，否则整体偏移 300–600m。

### 2.8.2 轨迹入库流水线

```
GPX/KML 上传 → 解析（gpxpy）→ 清洗（去跳点、去静止漂移）
  → Douglas-Peucker 抽稀（ε=4m，山地 6m）
  → 写 geography(LineString) 简化线（预览用，通常 < 2000 点）
  → 全量 geobuf 存对象存储（详情/导出用）
  → 计算 bbox、累计爬升（带阈值滤波，去掉 <3m 的抖动）
```

### 2.8.3 空间查询

```sql
-- 视野内路线（bbox 预筛 + 精确相交）
select id, name, distance_km
from trail
where bbox && ST_MakeEnvelope(:x1,:y1,:x2,:y2,4326)::box2d
  and ST_Intersects(geom_simpl, ST_MakeEnvelope(:x1,:y1,:x2,:y2,4326))
limit 200;

-- 附近路线（按距离）
select id, name, ST_Distance(geom_simpl, :pt::geography) as d
from trail
where ST_DWithin(geom_simpl, :pt::geography, 3000)
order by d limit 50;
```

## 2.10 高并发设计

| 问题 | 方案 |
|---|---|
| 读多写少 | 三级缓存：本地 LRU（1s 级）→ Redis → PG；热点 key 本地兜住 80% |
| 缓存穿透 | 空值缓存 60s + 布隆过滤器（景点 / 路线 id） |
| 缓存击穿 | 单飞（Redis `SET NX` 互斥），只允许一个请求回源 |
| 缓存雪崩 | TTL 加 ±10% 抖动；启动分批预热；Redis 主从 + 哨兵 |
| 写热点（点赞） | Redis 计数 + 异步批量落库（30s 一次），失败重试 |
| 限流 | Nginx `limit_req`（IP 级）+ 应用层 Redis 令牌桶（用户级，Lua 原子） |
| 削峰 | 发帖 / 图片处理入队，接口只做校验与落库，立即返回 |
| 大表 | `post` 按月分区；`favorite` 按 user_id 哈希分 16 片（预案） |
| 无状态扩展 | JWT + Redis，会话不落本地；K8s HPA 按 CPU/QPS 扩 |
| 推送 | WebSocket 连接用 Redis Pub/Sub 广播，网关按 uid 路由 |
| 降级 | Redis 故障 → 关闭计数与推荐，只保核心读；匹配降级为「热门搭子」 |

**容量估算（10 万 DAU）**

- 读 QPS 峰值 ≈ 800，写 ≈ 50；单机 4 worker 可扛，双副本冗余。
- Redis 内存：会话 10 万 × 0.5KB ≈ 50MB；缓存 2GB；GEO 索引 10 万点 ≈ 20MB。
- PG：日增帖子 5k、评论 3w，一年约 15GB（含索引）。

## 2.11 「附近的人」精确匹配

### 2.11.1 目标

在保证隐私的前提下，回答「谁此刻离我 3 公里内，且和我玩得到一起」。

### 2.11.2 三层过滤

```
① 粗筛（Redis GEO）
   GEOADD nearby:{city} lng lat {uid}          # 位置更新时写入
   GEOSEARCH nearby:{city} FROMMEMBER {me} BYRADIUS 5 km ASC COUNT 200

② 精算（PostGIS）
   ST_DWithin(geom, :pt, 5000) + ST_Distance 取米级距离

③ 重排（应用层）
   score = 0.4×距离衰减(exp(-d/1.5km))
         + 0.3×兴趣相似(Jaccard of tags)
         + 0.2×活跃度(最近 30 分钟在线)
         + 0.1×信誉分
```

### 2.11.3 精度的关键处理

1. **坐标脱敏**：入库前把真实坐标吸附到 geohash6（约 1.2km × 0.6km）网格中心，再加 ±150m 随机抖动。**存的是模糊点，不是真实点**，即使库被拖也无法还原精确位置。
2. **距离分档显示**：「500m 内 / 1km / 3km / 5km」，不显示精确米数，避免三角定位。
3. **双向授权**：只有在双方都点「可见位置」后才交换精确点；聊天中默认只显示区域。
4. **时效**：位置 30 分钟过期（Redis TTL + `presence.updated_at` 兜底），关闭 App 后不再出现。
5. **反作弊**：位置跳变检测（相邻两次上报速度 > 200km/h 判异常，丢弃并降权）、同设备多账号聚类、虚拟定位特征识别。
6. **性别 / 隐私开关**：默认只对「同性别或已互关」可见，可完全关闭。

### 2.11.4 为什么用 GEO + PostGIS 双写

Redis GEO 负责**低延迟粗筛**（O(log N + M)），PostGIS 负责**可审计的精算与空间联合查询**（例如「附近 3km 内、标注过露营点的用户」）。两者职责不同：前者是热路径，后者是复杂条件与数据一致性来源。
