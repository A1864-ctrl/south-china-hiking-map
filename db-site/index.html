落地时真踩到的三个坑PITFALLS

这些不是推测，是导入时逐条报错、逐条修出来的。

① SRID 4326 的轴序是「纬度在前」

按 GIS 圈习惯写 POINT(lng lat) 会直接崩：

ERROR 3617 (22S03): Latitude 113.324500
is out of range in function st_geomfromtext

-- 错：113.32 被读成纬度
ST_GeomFromText('POINT(113.3245 23.1066)', 4326)

-- 对：纬度在前
ST_GeomFromText('POINT(23.1066 113.3245)', 4326)

-- 或显式声明轴序，保留书写直觉
ST_GeomFromText('POINT(113.3245 23.1066)', 4326,
                'axis-order=long-lat')

危险点：只有空间函数会报错，普通 DECIMAL 的 lat/lng 列不会。两种顺序混用时最容易埋雷。

② 空间索引的列必须 NOT NULL

buddy_post.geom 原本带 DEFAULT NULL 又建了空间索引，建表直接失败：

ERROR 1252 (42000): All parts of a
SPATIAL index must be NOT NULL

-- 改成 NOT NULL 后通过
geom POINT SRID 4326 NOT NULL
     COMMENT '目的地坐标，发起招募必须选点'

产品上也更合理：没有目的地的招募帖，本来也没法做距离匹配。

③ 这个实例上 yejing_app 认证不上

账号建好后 hash、host、属性、SHOW CREATE USER 与能登录的 yj_app 逐字相同，但无论 FLUSH PRIVILEGES / RENAME USER / 换 caching_sha2_password 都返回 1045。

查过 HEX(user) 无隐藏字符、User_attributes 为 NULL、无 role、未锁定、密码未过期。判断为该实例的 ACL 残留（无管理员权限，没能重启服务复验）。

最终账号名取 yj_app / yj_ro。换机器部署若没这问题，改回 yejing_app 即可。

顺带修的幂等性问题

核心查询集里的会话签发语句重复执行会撞主键：

Duplicate entry 'a1b2c3d4...' for key
'user_session.PRIMARY'

-- 脚本要能反复跑，加幂等处理
INSERT INTO user_session (...) VALUES (...)
ON DUPLICATE KEY UPDATE
  last_expires_at = NOW(),
  revoked_at = NULL;

答辩现场演示两次不会翻车。

怎么跑起来RUN

建库脚本在项目 db/ 目录，也可用桌面的完整备份直接恢复。

# 一键建库 + 结构验收 + 功能验证
MYSQL_PWD='你的root密码' python db/setup.py

# 或者手动按顺序导入
mysql -uroot -p < db/01_schema.sql      # 23 表 + 视图 + 触发器
mysql -uroot -p < db/02_seed.sql        # 演示数据
mysql -uroot -p < db/04_user.sql        # 应用账号（最小权限）
mysql -uroot -p yejing < db/03_queries.sql   # 26 条核心查询

# 应用连接串
mysql+pymysql://yj_app:YeJing2026_App@127.0.0.1:3306/yejing?charset=utf8mb4
